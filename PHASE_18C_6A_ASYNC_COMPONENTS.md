# Phase 18C.6A — Isolated asynchronous components

`BootstrapAckDecoder` accepts exactly one newline-terminated acknowledgment and at most 4096 bytes of total output. It decodes UTF-8 strictly after frame assembly, handles native CRLF, rejects duplicate keys including escaped equivalents, and permits only the flat JSON acknowledgment schema. Nested values, BOMs, malformed JSON, trailing/second frames, truncation and mismatched receipt/nonce/digest are rejected. No raw frame or parser exception is logged or returned. Expected values are copied at construction.

`superviseBootstrap` uses asynchronous `spawn` with private redirected streams, no shell, hidden Windows launch and an explicitly supplied environment. The caller must choose the trusted fixed executable and keep secrets out of arguments/environment; this generic component does not establish executable identity or a pipe ACL. It writes bounded input privately, observes stream/process errors, rejects any stderr output, applies an overall deadline and accepts success only after a valid acknowledgment plus clean helper `close` with exit code zero. Exit alone is insufficient because output streams must finish first.

Abort or failure irreversibly enters cleanup: stop input, kill the owned process, and wait for close within a separate bounded cleanup interval. If close never arrives, retry forceful termination, destroy streams, unref the child and reject. This is a bounded failure result, not a claim that an unsuccessful OS kill terminated the process. The supervisor does not own arbitrary descendant trees; the existing native helper's Job Object remains responsible for its stub when connected in a later phase. Late data/errors/close events cannot grant success or settle twice. Error handlers remain safe for late events.

Focused tests use real Node stub children and simulated stubborn/event-race children. They exercise decoder limits/strictness, event-loop responsiveness, valid acknowledgment followed by failing exit, missing acknowledgment, stderr, spawn failure, timeout/abort with actual child reaping, broken input, bounded failed cleanup and late events.

No existing transport, authority, native helper, launcher, HTTP/WS route, UI or camera IPC is modified or imported. Connecting these components to the native bootstrap transport remains Phase 18C.6B work; no production integration is enabled.
