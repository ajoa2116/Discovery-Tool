`InstalledRootAdmission` is an internal observation helper, not connected to the production launcher, artifact trust, staged package admission or authentication. It reuses `WindowsBoundary.RequireUnelevated` and the native artifact verifier's fixed-disk, reparse rejection, retained read-sharing handles and kernel volume/file identity approach. It does not change `VerifiedBackendArtifacts` or its 64-file/128 MiB/256 MiB limits.

Strict `Verify` checks the root, every ancestor to the drive root, and every present payload file/directory. Local fully qualified canonical paths are required; device/UNC/drive-relative/ADS/traversing/ambiguous paths deny. Open-reparse handles, kernel final names and file IDs reject junctions, reparse points, aliases and redirection. File hard links deny. Missing/unreadable paths, unreadable descriptors, unsupported ACE types, excessive content or unstable observations deny with a reason and path. Payload observation is bounded to 64 files and 64 directories, with at most 64 ancestors; this does not enlarge any manifest allowance or prove the directory is a release payload.

Owner/group/DACL bytes are obtained through retained handles. Windows `AccessCheck(MAXIMUM_ALLOWED)` evaluates a duplicated live unelevated interactive token, including deny-only groups and implicit owner control. Granted write/append/EA/attributes, delete, delete-child, WRITE_DAC or WRITE_OWNER deny executable content. Existing ancestors deny deletion, delete-child, ACL/ownership and EA/attribute mutation; creating unrelated siblings alone is not treated as replacement of an existing protected path. Payload directories additionally deny creation rights.

For other users, a conservative DACL check rejects dangerous allow ACEs to any SID except SYSTEM, Administrators and TrustedInstaller. Unknown accounts/groups are not presumed privileged; inherited effective ACEs are examined and inherit-only ACEs are not applied to the current object. Ordinary ownership denies unless an effective OWNER RIGHTS deny suppresses implicit WRITE_DAC and the remaining checks pass. Unsupported object/callback ACEs and null DACLs deny. This deliberately may reject a safe ACL whose dangerous allow would be overridden by another deny; it does not impersonate or enumerate every possible user. Machine privilege assignments, hostile administrators/kernel/filesystem providers, malicious token injection and arbitrary in-process compromise are not certified.

Handles and descriptor snapshots are rechecked against newly opened intended paths before the result, then disposed on every outcome. Facts include role/path, owner, granted/forbidden masks, descriptor bytes and kernel identity. `InstalledRootAdmitted` means only that this strict observed ACL/path scope passed; it is not release or loading authorization. Every result has `ProductionAuthority:false` and `RaceFree:false`. Content hashes, release signatures, mapped-code integrity, future file additions, races after disposal and production dependency closure remain unproved.

The independent console fixture compiles only the new helper, existing `WindowsBoundary` and its test source into an external temporary output. No production CLI, installer or privileged service is added. Synthetic ACL changes affect only private fixture files/directories. Previously acquired WRITE_DAC handles restore original DACLs even after OWNER RIGHTS suppression. Those retained restoration capabilities are fixture machinery, not protected production installation evidence.
