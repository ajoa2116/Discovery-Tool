# Phase 18C.5 — Awaited bootstrap delivery

This supersedes the synchronous-only issuance contract described in Phase 18C.1/18C.3. `issueBootstrap(signal?)` now always returns a Promise. Callers must await it before treating delivery as successful. `TrustedBootstrapDelivery.deliver` accepts synchronous `void` or `Promise<void>` confirmation and an optional cancellation signal. Existing synchronous transports remain compatible, but still block during their own execution; this phase does not change the Phase 18C.3 transport.

Capabilities remain pending and nonredeemable until delivery resolves and authority rechecks expiry with its injected clock. Synchronous return, asynchronous resolution and exceptions all pass through the same activation check. Rejection, cancellation, disposal or expiry invalidates the capability. Disposal/cancellation reject pending issuance without waiting for transport acknowledgment, signal cancellation to delivery and prevent late success from reviving authority. Late rejected delivery promises remain observed. Cancellation after completed issuance is not session revocation; use explicit revocation for an issued session.

The pending-operation set and token store are bounded. Single-use synchronous redemption remains atomic within the authority's JavaScript execution context. Delivery implementations must provide their own bounded I/O and honor cancellation where possible: invalidating authority does not forcibly stop an uncooperative transport, erase a secret already received, or prevent a blocking synchronous call. No HTTP/WS/UI/launcher/native IPC integration is added, and the same-user bearer-secret/process threat limitations remain unchanged.

Focused tests cover delayed acknowledgment, pending redemption, asynchronous rejection, exact expiry during synchronous/asynchronous delivery, abort/disposal before and during delivery, late success/rejection, same-turn acknowledgment/cancellation races and double redemption. Existing authority lifecycle and real private-transport tests are adapted to await issuance; transport implementation is unchanged.
