# Phase 18C.6B — Asynchronous isolated bootstrap transport

`PrivateBootstrapTransport.deliver` now returns a Promise and uses Phase 18C.6A `superviseBootstrap`, forwarding the authority's cancellation signal. The fixed helper image, restricted environment and private OFFER input remain unchanged. Secrets remain absent from arguments, environment, URLs and logs. A fresh nonce plus receipt ID and capability digest bind the strict, bounded acknowledgment decoder to each delivery. Pre-abort/expired receipts are rejected, and cancellation/expiry are checked again after helper completion. Phase 18C.5 authority additionally rechecks its injected clock before activation and retains single-use redemption.

Native implementation is unchanged: restricted pipe ACL, reciprocal owned child PID/session/image verification, ACK → COMMIT → DONE and stub exit are preserved. Node reports success only after exactly one valid DELIVERED frame and clean helper `close`, not receipt alone. Malformed/duplicate/incomplete output, stream failures, stderr, nonzero exit, abort and timeout cannot become late success. The overall delivery deadline is eight seconds with a separate two-second cleanup bound; the helper's Job owns its stub. Failure invalidates authority immediately while asynchronous cleanup completes. A failed OS kill is reported as failure, not guaranteed process termination.

Focused coverage includes actual Windows ACL/first-instance checks, normal delivery, malformed/duplicate/oversized native frames, wrong acknowledgment, protocol replay, timeout, disconnect, peer mismatch, cancellation/disposal during real delivery, event-loop responsiveness and pre-abort/expiry. Decoder/supervisor and authority race suites remain in scope. Callers must return or await the delivery Promise; tests are updated accordingly.

This remains an isolated stub proof. No launcher/UI/HTTP/WS/camera integration or running-app restart is performed. Same-user injection, replaced development binaries and bearer-secret theft remain outside the IPC proof. Persistent owned UI delivery is still unimplemented.
