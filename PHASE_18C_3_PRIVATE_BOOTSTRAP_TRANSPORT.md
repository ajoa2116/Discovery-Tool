# Phase 18C.3 — Isolated Windows private bootstrap transport

`PrivateBootstrapTransport` implements the Phase 18C.1 synchronous delivery interface using a fixed, owned helper executable and `spawnSync`. It is Windows-only and has no production imports. The helper launches only its own stub recipient, never the UI, application launcher or camera host. The separate .NET project has no package dependencies; it links the existing WindowsBoundary/Wire security primitives as source without changing them or the CameraBrowserHost project.

Node sends the bootstrap over private redirected stdin, with a fresh random nonce and nonsecret receipt ID. The helper creates a protected Windows named pipe before launching its child. Enforcement includes current interactive logon SID DACL, noninherited server handles, random endpoint name, first-instance and remote-client rejection, kernel-reported intended child PID, same session and exact image path. The stub reciprocally verifies the pipe server PID/session/image. Both reject elevated/noninteractive execution. An owned kill-on-close Job Object bounds the child lifetime.

Only after peer verification does the helper send OFFER. The stub acknowledges the exact ID, nonce and SHA-256 capability digest; the helper validates ACK, sends COMMIT, requires DONE and a successful child exit, then reports DELIVERED privately to Node. This confirms receipt by the stub, not delivery to a browser or use of an application session. The stub exits without retaining credentials. The helper does not redeem authority: Phase 18C.1 enables redemption only after synchronous delivery returns. Any failed/expired delivery throws a generic error, invalidating the bootstrap. A duplicate ACK violates the next expected state; the bootstrap itself remains single-use through the authority.

Frames use strict UTF-8, exact shape/duplicate-key validation, 16 KB bounds and deadlines. The overall Node call is bounded to eight seconds and 4 KB output. Successful acknowledgments bind to the fresh nonce and receipt. No tokens occur in URLs, arguments, environment, files or logs; raw stderr/native exceptions are not forwarded. Node uses a restricted environment. Secrets necessarily exist briefly in process memory and private stream buffers; there is no secure-memory-erasure claim.

All normal/failure paths dispose pipe/process/Job handles; the helper explicitly terminates and waits for its owned child. Parent helper termination closes the Job and ends the stub. Names and broker PID in child arguments are nonsecret rendezvous data. The development output path is not a protected/signed deployment: same-user injection/debugging, binary replacement, bearer-secret theft and administrator compromise remain outside the proof. No cross-account attacker was provisioned; the actual DACL is inspected instead.

Focused tests exercise the real descriptor/first-instance boundary, valid receipt before authority activation, malformed/duplicate/oversized frames, wrong acknowledgment nonce, protocol replay, timeout, disconnect and incorrect expected peer PID. The wrong-peer fixture deliberately mismatches the expected PID and verifies denial; it does not claim a complete adversarial process-race test. Existing authority lifecycle tests remain in scope. No application, HTTP/WS listener, native camera window or camera/network operation is started.

This is a blocking isolated proof, not an event-loop-friendly production transport. Any later asynchronous production design must retain the pending/not-redeemable delivery state and invalidate it on failure. Stop after this phase; trusted UI delivery remains unimplemented.
